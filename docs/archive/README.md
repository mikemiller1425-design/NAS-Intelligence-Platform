# Archive Purpose

The archive exists to preserve completed, superseded, or historical documentation that should remain available for traceability but should not drive active blueprint decisions.

## What belongs here

- finished audit reports;
- retired or superseded specification snapshots;
- historical reconciliation artifacts;
- completed handoff materials;
- evidence that is no longer active but still useful for reference.

## What does not belong here

- active policy;
- current source authority;
- live implementation code;
- temporary working notes that are still shaping decisions;
- anything that could be mistaken for the authoritative current blueprint.

## Archive rules

- Archive content is read-only by default.
- Archived material must not silently override active documents.
- If a conflict exists between archive content and active blueprint content, the active document wins until a deliberate governance change is made.
- Archive entries should be labeled clearly with date, reason, and supersession status when applicable.

## Intended use

The archive helps the team answer questions like:

- what did we believe at a specific point in time?
- what was audited and when?
- which decisions were replaced by newer ones?
- what evidence supported a completed milestone?

## Relationship to the blueprint

The archive is a memory layer, not a control layer. It preserves history so the active blueprint can stay lean, current, and safe.
