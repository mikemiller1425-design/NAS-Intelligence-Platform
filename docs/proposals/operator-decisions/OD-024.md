## The decision being requested

Does V1 reproduce symbolic links and hard links faithfully, or declare link reproduction out of scope with a stop condition?

## Why it matters

Operation entry types are copy, move, rename, quarantine, skip. The identity model requires a symlink-recreation type **or** an explicit out-of-scope declaration — neither exists. The preservation model requires linking the remainder of a hard-link set, which no entry type can express. Two fixtures are unimplementable as written.

## Safe options

**1. Reproduce faithfully**

Add entry types for symlink recreation and hard-link linking.

*Tradeoff:* Preserves link topology, which the preservation model treats as required on capable adapters. More implementation surface, and link support varies sharply by adapter.

**2. Declare out of scope with a stop condition**

Links are inventoried, never copied; any operation on a link stops and routes to review.

*Tradeoff:* Much smaller surface. Every link becomes an operator decision, which may be a large manual burden depending on how many links the corpus contains.

**3. Reproduce symlinks, defer hard links**

Split the two.

*Tradeoff:* Symlinks are simpler than hard-link sets. Leaves hard-link sets stopping at review, which is safe but partial.

## Recommendation

**Option 1 if the corpus contains meaningful link structure; Option 2 if it does not.** This genuinely depends on the data, which only the operator can assess. A read-only count of links would settle it — but that count requires G4, so it cannot inform this decision beforehand without a deliberate ordering choice.

## What the operator must supply

Which option, and if Option 2, confirmation that every link becoming a review item is acceptable.

## Default behaviour if unresolved

The symlink rung and the property-reproduction rung stop.

## Evidence required to close

A recorded scope decision reflected in the operation model's entry types.

## Cost of changing the decision later

Moderate to high. Adding link reproduction later means revisiting the copy engine and its crash rows.
