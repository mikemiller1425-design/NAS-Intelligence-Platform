## The decision being requested

Which migration-control directory schema is canonical — the assignment layout or the operations-manual layout?

## Why it matters

The control root holds journal segments, checkpoints, the nonce ledger, the database, and recovery sidecars. Its names must be fixed before real control directories are created.

## Safe options

**1. Assignment layout**

`00_Consolidation_Source` … `logs`, already named canonical in the taxonomy model.

*Tradeoff:* Already the documented default; lowest churn.

**2. Operations-manual layout**

`01_Inventory` … `08_Checkpoints`.

*Tradeoff:* Closer to the original manual, but would require changing the taxonomy model and the example config.

**3. A merged third layout**

Take the best of both.

*Tradeoff:* Highest churn; needs a fresh review of every path reference.

## Recommendation

**Option 1.** It is already recorded as the canonical default with the alternate preserved as a recorded variant, so choosing it is a confirmation rather than a change.

## What the operator must supply

Confirmation of the final directory names, or a replacement list.

## Default behaviour if unresolved

Fixture-only implementation proceeds on config-driven defaults. Real control directories cannot be created.

## Evidence required to close

A confirmed directory list recorded in the taxonomy model.

## Cost of changing the decision later

Moderate. Renaming after control data exists means moving journals and checkpoints, which is a migration in itself.
